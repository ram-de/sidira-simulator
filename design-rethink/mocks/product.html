HOW THE CAPTURE RUNS

A Playwright walker, authenticated per role, four passes to a snapshot.

You name 5–10 priority capabilities, 1–3 entry URLs each, and one test login per role into a sandbox tenant — never production. The walker does the rest, every Monday at 04:00 UTC, in roughly 40 minutes of CI.

→

Walk, per role

Logs in as each declared role into the sandbox, then walks each flow ~3 hops deep — screens, components, states, copy, transitions.

→

Synthesize reverse-PRD

Goal, roles, flow-per-role, success criteria, edge cases, and the implicit metric the surface optimizes for.

→

Emit reverse-Figma

Structured screens, components with semantic roles, per-state copy, and prototype transitions — Figma-level abstraction, no pixels.

▪

Tag & diff

Versions the snapshot and diffs it against last week. Promotion to “latest” is gated on a human reviewing the diff.

INSIDE A CAPABILITY

Two files per capability. Nothing more, nothing less.

Screenshots and pixel data are out — a team doesn’t submit pixels for the proposed change, so symmetry says we don’t capture them either. Copy lives inline in the component nodes. The value is this product’s specifics, never generic UX advice.
